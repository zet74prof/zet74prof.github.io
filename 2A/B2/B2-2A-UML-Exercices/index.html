    Exercice 1 : Navigabilité

    Contexte : Vous concevez un système de gestion pour une bibliothèque universitaire avec les contraintes suivantes : - Fonctionnalité principale : Les étudiants doivent pouvoir consulter la liste des livres qu’ils ont empruntés (historique d’emprunts). - Fonctionnalité secondaire : Le système doit permettre d’afficher les informations d’un livre (titre, ISBN, auteurs) lorsqu’un étudiant le sélectionne. - Contrainte technique : Pour des raisons de performance, on évite les requêtes bidirectionnelles inutiles. La base de données est optimisée pour les lectures fréquentes (ex : afficher les livres d’un étudiant), mais pas pour les mises à jour complexes.

    Classes à modéliser : - Etudiant : nom, prénom, numéroEtudiant. - Livre : titre, ISBN, datePublication. - Auteur : nom, nationalité.

    Consignes : 1. Dessinez un diagramme de classe avec les associations entre Etudiant, Livre, et Auteur. 2. Définissez la navigabilité pour chaque association en respectant les exigences suivantes : - Un étudiant doit pouvoir accéder directement à la liste des livres qu’il a empruntés (pour son historique). - Un livre doit pouvoir accéder directement à ses auteurs (pour afficher les informations bibliographiques). - Aucune autre navigabilité n’est autorisée (ex : on ne peut pas naviguer de Auteur vers Livre ou de Livre vers Etudiant). 3. Justifiez chaque choix en expliquant pourquoi les autres navigabilités sont exclues (ex : performance, simplicité, besoins métiers).

    Variante pour aller plus loin

    Nouvelle exigence : Le système doit maintenant permettre aux utilisateurs de rechercher tous les livres écrits par un auteur spécifique (ex : page "Œuvres de Victor Hugo"). Question : 1. Comment modifieriez-vous le diagramme pour supporter cette nouvelle fonctionnalité ? 2. Quels impacts cela aurait-il sur : - La navigabilité ? - Les performances du système ? - La complexité du code ?

    Exercice 2 : Héritage

    Contexte : Vous travaillez pour une entreprise de développement logiciel qui souhaite moderniser son système de gestion des ressources humaines. L’entreprise emploie différents types de collaborateurs : - Développeurs (spécialisés en frontend, backend, ou full-stack). - Chefs de projet (responsables de l’organisation des équipes et des livrables). - Testeurs (chargés de la qualité logicielle).

    Tous les employés partagent des attributs communs (nom, prénom, identifiant, salaire de base), mais chaque rôle a des attributs et méthodes spécifiques : - Un Développeur a un langagePrincipal (ex : Java, C#) et une méthode coder(). - Un Chef de projet a un nombreProjets en cours et une méthode planifierSprint(). - Un Testeur a un outilsTest (ex : Selenium, JUnit) et une méthode executerTests().

    Exigence supplémentaire : L’entreprise souhaite pouvoir calculer le salaire mensuel de chaque employé, qui dépend de son rôle : - Développeur : salaire de base + prime de 10% (pour la technicité). - Chef de projet : salaire de base + prime de 20% (pour la responsabilité). - Testeur : salaire de base + prime de 5% (pour la rigueur).

    Consignes : 1. Mopdélisez ce système. 2. Ajoutez une classe Entreprise qui : - Contient une liste d’Employe (polymorphisme). - A une méthode calculerMasseSalariale() qui retourne le total des salaires de tous les employés.

    Exercice 3 : Classe-Association

    Contexte : Vous concevez un système de gestion pour une entreprise de conseil en informatique. Les consultants de l’entreprise travaillent sur différents projets, et chaque consultant peut être affecté à plusieurs projets simultanément. De même, un projet peut impliquer plusieurs consultants.

    Exigence fonctionnelle : Pour chaque affectation d’un consultant à un projet, il est nécessaire de stocker : - La date de début de l’affectation. - La date de fin prévue (ou réelle). - Le rôle du consultant dans le projet (ex : "Développeur", "Chef de projet", "Analyste").

    Consignes : Modélisez ce système.
