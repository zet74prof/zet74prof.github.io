    Automatisation avec Ansible pour la Réinstallation des PC sous Ubuntu

    Contexte : Projet de réinstallation des postes BTS SIO

    1. Introduction à Ansible

    1.1 Qu’est-ce qu’Ansible ?

    • Définition : Outil d’automatisation open-source pour le provisionnement, la configuration et la gestion de parcs informatiques (serveurs, postes clients, réseaux).
    • Avantages :
      • Agentless : Utilise SSH (pas d’agent à installer sur les machines cibles).
      • Idempotent : Une tâche exécutée plusieurs fois produit le même résultat.
      • Langage simple : Syntaxe en YAML (lisible et facile à apprendre).
      • Modulaire : Utilisation de modules pour des tâches spécifiques (ex. : apt, copy, template).
    • Cas d’usage : Déploiement de configurations, gestion de paquets, orchestration de tâches complexes.

    1.2 Pourquoi Ansible pour la réinstallation des PC ?

    • Automatisation : Réduire le temps de réinstallation manuelle (ex. : 20 PC → 1 commande).
    • Cohérence : Garantir que tous les postes ont la même configuration (logiciels, utilisateurs, permissions).
    • Reproductibilité : Scripts réutilisables pour les futures réinstallations.
    • Adapté à Ubuntu : Modules natifs pour la gestion des paquets (apt), des utilisateurs (user), et des services (systemd).

    2. Prérequis et Environnement

    2.1 Matériel et Logiciels Nécessaires

    Élément Description
    Machine de contrôle 1 PC sous Ubuntu 26.04 avec Ansible installé (ex. : R20925).
    Machines cibles PC des salles (ex. : R209-01 à R209-20) avec Ubuntu 26.04 fraîchement installé.
    Accès réseau SSH activé sur les machines cibles (sudo apt install openssh-server).
    Utilisateur Compte avec droits sudo sur toutes les machines (ex. : etudiant ou admin-sio).
    Clé SSH Paire de clés SSH pour une authentification sans mot de passe (recommandé).

    2.2 Installation d’Ansible sur la Machine de Contrôle

    # Mettre à jour les dépôts
sudo apt update

# Installer Ansible
sudo apt install ansible -y

# Vérifier la version
ansible --version

    2.3 Configuration de Base

    • Fichier d’inventaire (/etc/ansible/hosts) : Liste des machines cibles. 
      [bts_sio_pcs]
R209-01 ansible_host=192.168.1.101
R209-02 ansible_host=192.168.1.102
# ...
R211-20 ansible_host=192.168.1.120

[bts_sio_pcs:vars]
ansible_user=admin-sio
ansible_ssh_private_key_file=~/.ssh/id_rsa_bts_sio
    • Fichier de configuration (/etc/ansible/ansible.cfg) : 
      [defaults]
inventory = /etc/ansible/hosts
remote_user = admin-sio
private_key_file = ~/.ssh/id_rsa_bts_sio
host_key_checking = False

    3. Concepts Clés d’Ansible

    3.1 Terminologie

    Terme Description
    Playbook Fichier YAML décrivant une série de tâches à exécuter (ex. : install_software.yml).
    Tâche Action élémentaire (ex. : installer un paquet, copier un fichier).
    Module Unité de code réutilisable (ex. : apt, copy, template).
    Inventaire Fichier listant les machines cibles (groupes et variables).
    Rôle Collection de playbooks, tâches et fichiers organisés pour une fonction spécifique.
    Facts Informations collectées sur les machines cibles (ex. : OS, IP, CPU).

    3.2 Structure d’un Playbook

    Exemple : install_basic_software.yml

    ---
- name: Installer les logiciels de base pour les PC BTS SIO
  hosts: bts_sio_pcs
  become: yes  # Exécute avec sudo

  tasks:
    - name: Mettre à jour les dépôts APT
      ansible.builtin.apt:
        update_cache: yes

    - name: Installer les paquets essentiels
      ansible.builtin.apt:
        name:
          - git
          - curl
          - wget
          - net-tools
          - htop
          - vim
        state: present

    - name: Installer Visual Studio Code (via snap)
      ansible.builtin.snap:
        name: code
        state: present
        classic: yes

    4. Étapes pour la Réinstallation des PC

    4.1 Préparation des Machines Cibles

    1. Installer Ubuntu 26.04 sur chaque PC (via clé USB ou PXE).
    2. Configurer un utilisateur admin avec droits sudo : 
       sudo adduser admin-sio
 sudo usermod -aG sudo admin-sio
    3. Activer SSH et autoriser l’accès depuis la machine de contrôle : 
       sudo apt install openssh-server -y
 sudo systemctl enable --now ssh
 sudo ufw allow ssh
    4. Ajouter la clé SSH publique de la machine de contrôle dans ~/.ssh/authorized_keys sur chaque PC.

    4.2 Organisation des Fichiers Ansible

    /opt/ansible-bts-sio/
├── inventory/
│   ├── hosts           # Fichier d'inventaire
│   └── group_vars/     # Variables par groupe
│       └── bts_sio_pcs.yml
├── playbooks/
│   ├── install_basic_software.yml
│   ├── configure_users.yml
│   ├── deploy_dotnet.yml
│   └── harden_system.yml
├── roles/
│   └── common/         # Rôle pour les tâches communes
└── ansible.cfg         # Configuration globale

    4.3 Playbooks pour la Réinstallation

    A. Installation des Logiciels de Base

    Fichier : playbooks/install_basic_software.yml

    ---
- name: Installer les logiciels de base
  hosts: bts_sio_pcs
  become: yes

  tasks:
    - name: Mettre à jour APT
      ansible.builtin.apt:
        update_cache: yes

    - name: Installer les outils système
      ansible.builtin.apt:
        name:
          - git
          - curl
          - wget
          - net-tools
          - htop
          - vim
          - gnupg
          - software-properties-common
        state: present

    - name: Ajouter le dépôt Microsoft pour .NET
      ansible.builtin.apt_repository:
        repo: "deb [arch=amd64] https://packages.microsoft.com/ubuntu/26.04/prod {{ ansible_distribution_release }} main"
        state: present
        filename: microsoft-prod

    - name: Installer .NET SDK 8.0
      ansible.builtin.apt:
        name: dotnet-sdk-8.0
        state: present

    - name: Installer Visual Studio Code
      ansible.builtin.snap:
        name: code
        state: present
        classic: yes

    - name: Installer Docker
      ansible.builtin.apt:
        name:
          - docker.io
          - docker-compose
        state: present

    - name: Ajouter l'utilisateur admin-sio au groupe docker
      ansible.builtin.user:
        name: admin-sio
        groups: docker
        append: yes

    B. Configuration des Utilisateurs et Permissions

    Fichier : playbooks/configure_users.yml

    ---
- name: Configurer les utilisateurs et permissions
  hosts: bts_sio_pcs
  become: yes

  tasks:
    - name: Créer les utilisateurs étudiants (ex. : etu1, etu2)
      ansible.builtin.user:
        name: "{{ item }}"
        state: present
        groups: "students"
        shell: /bin/bash
        password: "$6$rounds=5000$salt$hashed_password"  # Utiliser `mkpasswd` pour générer
      loop:
        - etu1
        - etu2

    - name: Créer le groupe 'students'
      ansible.builtin.group:
        name: students
        state: present

    - name: Configurer les permissions sur /home/students
      ansible.builtin.file:
        path: /home/students
        state: directory
        owner: root
        group: students
        mode: '0770'

    - name: Déployer un script de bienvenue pour les étudiants
      ansible.builtin.copy:
        src: files/welcome_script.sh
        dest: /home/students/welcome.sh
        owner: root
        group: students
        mode: '0755'

    C. Déploiement de la Configuration Réseau

    Fichier : playbooks/configure_network.yml

    ---
- name: Configurer le réseau pour le domaine bts-sio.local
  hosts: bts_sio_pcs
  become: yes

  tasks:
    - name: Configurer le nom d'hôte (hostname)
      ansible.builtin.hostname:
        name: "{{ inventory_hostname }}"

    - name: Configurer le fichier /etc/hosts
      ansible.builtin.lineinfile:
        path: /etc/hosts
        line: "192.168.1.100  bts-sio-server bts-sio.local"
        state: present

    - name: Configurer le DNS pour le domaine local
      ansible.builtin.copy:
        src: files/resolv.conf
        dest: /etc/resolv.conf
        owner: root
        group: root
        mode: '0644'

    D. Sécurisation du Système

    Fichier : playbooks/harden_system.yml

    ---
- name: Appliquer des règles de sécurité de base
  hosts: bts_sio_pcs
  become: yes

  tasks:
    - name: Installer et configurer UFW (pare-feu)
      ansible.builtin.apt:
        name: ufw
        state: present

    - name: Autoriser SSH et HTTP/HTTPS
      ansible.builtin.ufw:
        rule: allow
        port: "{{ item }}"
      loop:
        - 22
        - 80
        - 443

    - name: Activer UFW
      ansible.builtin.ufw:
        state: enabled

    - name: Désactiver l'accès root en SSH
      ansible.builtin.lineinfile:
        path: /etc/ssh/sshd_config
        regexp: '^PermitRootLogin'
        line: 'PermitRootLogin no'
        state: present
      notify: Restart SSH

    - name: Désactiver la connexion par mot de passe SSH
      ansible.builtin.lineinfile:
        path: /etc/ssh/sshd_config
        regexp: '^PasswordAuthentication'
        line: 'PasswordAuthentication no'
        state: present
      notify: Restart SSH

  handlers:
    - name: Restart SSH
      ansible.builtin.service:
        name: ssh
        state: restarted

    5. Exécution des Playbooks

    5.1 Commandes de Base

    Commande Description
    ansible all -m ping Tester la connexion à toutes les machines.
    ansible bts_sio_pcs -m apt -a "name=vim state=present" --become Installer vim sur toutes les machines (avec sudo).
    ansible-playbook playbooks/install_basic_software.yml Exécuter le playbook d’installation des logiciels de base.
    ansible-playbook playbooks/*.yml Exécuter tous les playbooks dans l’ordre.

    5.2 Exécution Complète pour la Réinstallation

    # 1. Tester la connexion
ansible all -m ping

# 2. Exécuter les playbooks dans l'ordre
ansible-playbook playbooks/install_basic_software.yml
ansible-playbook playbooks/configure_users.yml
ansible-playbook playbooks/configure_network.yml
ansible-playbook playbooks/harden_system.yml

# 3. Vérifier l'état final
ansible all -a "uptime"  # Vérifier que les machines sont opérationnelles

    6. Bonnes Pratiques et Astuces

    6.1 Organisation du Code

    • Utiliser des rôles pour regrouper les tâches par fonctionnalité (ex. : roles/common, roles/dotnet).
    • Variables : Définir les variables dans group_vars/ ou host_vars/ pour une meilleure maintenabilité.
      Exemple : group_vars/bts_sio_pcs.yml 
      ---
dotnet_version: "8.0"
students:
  - etu1
  - etu2
    • Templates : Utiliser le module template pour générer des fichiers de configuration dynamiques (ex. : nginx.conf.j2).

    6.2 Gestion des Erreurs

    • Mode --check : Simuler l’exécution sans appliquer les changements. 
      ansible-playbook playbooks/install_basic_software.yml --check
    • Verbosité : Utiliser -v, -vv, ou -vvv pour déboguer. 
      ansible-playbook playbooks/install_basic_software.yml -vvv
    • Gestion des échecs : Utiliser ignore_errors: yes pour les tâches non critiques. 
      - name: Tâche non critique
  ansible.builtin.command: /usr/bin/risque
  ignore_errors: yes

    6.3 Optimisation

    • Parallélisme : Utiliser -f pour exécuter les tâches en parallèle (ex. : -f 10 pour 10 machines simultanées). 
      ansible-playbook playbooks/install_basic_software.yml -f 10
    • Cache des Facts : Activer le cache pour accélérer les exécutions répétées. 
      [defaults]
gathering = smart
fact_caching = jsonfile
fact_caching_connection = /tmp/ansible_facts

    9. Conclusion et Prochaines Étapes

    9.1 Résumé

    • Ansible permet d’automatiser la configuration des PC sous Ubuntu 26.04.
    • Les playbooks et rôles structurent les tâches pour une maintenance facile.
    • Les bonnes pratiques (variables, templates, cache) optimisent les performances.

    9.2 Prochaines Étapes pour les Étudiants

    • Aller plus loin : Explorer les modules docker_container, kubernetes, ou aws_s3 pour des cas d’usage avancés.
    • Projet fil rouge : Automatiser le déploiement d’une application full-stack (frontend + backend) avec Ansible.
    • Veille technologique : Suivre les mises à jour d’Ansible (ex. : Ansible Blog).

    10. Questions Fréquentes (FAQ)

    Q : Comment ajouter une nouvelle machine à l’inventaire ?

    R : Ajouter une ligne dans /etc/ansible/hosts :

    R212-01 ansible_host=192.168.1.150

    Puis tester avec ansible R212-01 -m ping.

    Q : Pourquoi une tâche échoue-t-elle avec "Permission denied" ?

    R : Vérifier que :

    1. L’utilisateur a les droits sudo sur la machine cible.
    2. La clé SSH est correctement ajoutée dans ~/.ssh/authorized_keys.
    3. Le playbook utilise become: yes.

    Q : Comment déboguer un playbook ?

    R : Utiliser :

    • -vvv pour afficher les détails d’exécution.
    • --check pour simuler sans appliquer.
    • ansible-lint pour vérifier la syntaxe.

    Q : Peut-on utiliser Ansible avec Windows ?

    R : Oui, avec le module winrm (Windows Remote Management). Exemple :

    - name: Exemple pour Windows
  hosts: windows_pcs
  gather_facts: no
  tasks:
    - name: Installer un logiciel
      ansible.windows.win_package:
        path: C:\installers\vscode.exe
        state: present
