    POO Cours

    Cours : Introduction à la Programmation Orientée Objet en C# (BTS SIO)

    Objectifs du cours

    • Comprendre les principes fondamentaux de la programmation orientée objet (POO).
    • Apprendre les concepts clés de la POO : classes, objets, propriétés, méthodes, héritage, encapsulation, polymorphisme.
    • Découvrir comment appliquer ces concepts en langage C#.

    Plan du cours

    1. Qu'est-ce que la Programmation Orientée Objet (POO) ?

    La POO est une approche de programmation basée sur l'utilisation d'objets pour modéliser des entités du monde réel ou abstrait. Elle repose sur les concepts suivants :

    • Classes : Modèles ou plans pour créer des objets. Une classe contient :
    • Attributs ou Propriétés : Représentent les caractéristiques ou états d'une entité (par exemple, un "Nom" ou un "Age").
    • Méthodes : Définissent les comportements ou actions possibles de cette entité (par exemple, "SePresenter" ou "CalculerSalaire").

    La classe agit comme une abstraction permettant de définir des objets partageant ces caractéristiques et comportements. - Objets : Instances concrètes des classes. - Encapsulation : Regroupement des données et des méthodes au sein d'une même entité. - Héritage : Capacité d'une classe à hériter des propriétés et méthodes d'une autre classe. - Polymorphisme : Capacité d'une entité à prendre plusieurs formes.

    2. Structure de base d'une classe en C

    Exemple simple

    public class Personne
{
    // Propriétés
    public string Nom { get; set; }
    public int Age { get; set; }

    // Constructeur
    public Personne(string nom, int age)
    {
        Nom = nom;
        Age = age;
    }

    // Méthodes
    public void SePresenter()
    {
        Console.WriteLine($"Bonjour, je m'appelle {Nom} et j'ai {Age} ans.");
    }
}

    Utilisation de la classe

    class Program
{
    static void Main(string[] args)
    {
        Personne personne = new Personne("Alice", 25);
        personne.SePresenter();
    }
}

    3. Les principes fondamentaux de la POO

    a) Encapsulation

    • Propriétés privées et accès via des getters/setters.
    • Exemple :
    public class CompteBancaire
{
    private double solde;

    public double Solde
    {
        get { return solde; }
        private set { solde = value; }
    }

    public void Deposer(double montant)
    {
        solde += montant;
    }
}

    b) Héritage

    • Une classe peut hériter d'une autre pour réutiliser son code.
    • Exemple :
    public class Animal
{
    // Attributs
    public string Nom { get; set; }
    public int Age { get; set; }

    // Constructeur
    public Animal(string nom, int age)
    {
        Nom = nom;
        Age = age;
    }

    // Méthode commune
    public void Manger()
    {
        Console.WriteLine($"{Nom} mange.");
    }
}

public class Chien : Animal
{
    public Chien(string nom, int age) : base(nom, age) { }

    public void Aboyer()
    {
        Console.WriteLine($"{Nom} aboie : Woof Woof !");
    }
}

public class Oiseau : Animal
{
    public int Envergure { get; set; } // En centimètres

    public Oiseau(string nom, int age, int envergure) : base(nom, age)
    {
        Envergure = envergure;
    }

    public void Voler()
    {
        Console.WriteLine($"{Nom}, avec une envergure de {Envergure} cm, vole dans les airs.");
    }
}

    c) Polymorphisme

    • Redéfinition des méthodes (override).
    • Exemple :
    public class Animal
{
    public virtual void FaireDuBruit()
    {
        Console.WriteLine("Un bruit général.");
    }
}

public class Chat : Animal
{
    public override void FaireDuBruit()
    {
        Console.WriteLine("Miaou !");
    }
}

public class Program
{
    static void Main(string[] args)
    {
        Animal monAnimal = new Chat();
        monAnimal.FaireDuBruit(); // Affiche "Miaou !"
    }
}

    4. Récapitulatif

    • La POO permet de structurer le code de manière claire et réutilisable.
    • En C#, les classes sont le point central de la POO.
    • Les concepts de base (encapsulation, héritage, polymorphisme) permettent de modéliser des problèmes complexes en utilisant des abstractions simples.

    5. Prolongement

    Pour aller plus loin : - Explorer les interfaces et les classes abstraites. - Comprendre les délégués et les événements. - Utiliser les collections génériques pour manipuler des ensembles d'objets.

    Exercice possible : Créez un système de gestion d'une bibliothèque où les livres et les magazines sont des types d'éléments distincts, mais partagent des fonctionnalités communes.
