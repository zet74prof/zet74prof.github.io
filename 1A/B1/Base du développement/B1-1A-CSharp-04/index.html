    B1 1A CSharp 04

    📌 Séance 4 : Les boucles (for, while, do-while, foreach)

    Objectifs pédagogiques : ✅ Comprendre le principe de la répétition en programmation et savoir choisir la bonne boucle selon le problème. ✅ Maîtriser la boucle for (nombre d’itérations connu). ✅ Maîtriser les boucles while et do-while (nombre d’itérations inconnu a priori). ✅ Découvrir le parcours de collections avec foreach. ✅ Utiliser break et continue pour contrôler le flux d’exécution. ✅ Éviter les pièges classiques : boucles infinies, condition de sortie jamais atteinte, compteur mal incrémenté.

    📚 Partie Cours

    🔹 1. Pourquoi des boucles ?

    1.1 Le problème

    Sans boucle, répéter une action 10 fois obligerait à écrire 10 fois le même code : 

    Console.WriteLine(1);
Console.WriteLine(2);
Console.WriteLine(3);
// ... et imaginez pour 1 000 répétitions !

    Analogie :

    "Une boucle est comme un tapis de course : tu répètes le même mouvement tant que la condition 'je continue' est vraie. Quand tu appuies sur Stop (la condition devient fausse), tu descends du tapis."

    1.2 Les deux grandes familles

    Situation Boucle adaptée Exemple
    On connaît à l’avance le nombre de répétitions for Afficher les tables de multiplication de 1 à 10.
    On ne connaît pas le nombre de répétitions while / do-while Lire des saisies jusqu’à ce que l’utilisateur tape "quit".
    On parcourt une collection foreach Afficher tous les éléments d’une liste.

    🔹 2. La boucle for

    2.1 Syntaxe

    for (initialisation; condition; incrémentation) {
    // Corps de la boucle (répété tant que la condition est vraie)
}
    Trois zones, séparées par des ; : 1. Initialisation : exécutée une seule fois, avant la boucle (généralement la déclaration du compteur). 2. Condition : expression booléenne évaluée avant chaque itération. Si elle est fausse dès le départ, le corps n’est jamais exécuté. 3. Incrémentation : exécutée après chaque itération (souvent i++).

    Ordre d’exécution : 

    initialisation → condition ? → corps → incrémentation → condition ? → corps → ... → condition fausse → sortie

    2.2 Exemple fondamental

    for (int i = 1; i <= 5; i++) {
    Console.WriteLine($"Itération n°{i}");
}
// Affiche :
// Itération n°1
// Itération n°2
// ...
// Itération n°5

    2.3 Variantes utiles

    // Compter à rebours
for (int i = 10; i >= 0; i--) {
    Console.WriteLine(i);
}

// Pas de 2
for (int i = 0; i <= 20; i += 2) {
    Console.WriteLine(i);
}

// Deux variables dans l'initialisation
for (int i = 0, j = 10; i < j; i++, j--) {
    Console.WriteLine($"i = {i}, j = {j}");
}

    2.4 Pièges classiques du for

    Piège Code Conséquence
    Condition jamais atteinte for (int i = 0; i > 10; i++) Boucle jamais exécutée (0 > 10 est faux).
    Oubli de l’incrémentation for (int i = 0; i < 10;) Boucle infinie (i vaut toujours 0).
    Sens inversé for (int i = 10; i >= 0; i++) Boucle infinie (i grandit alors que la condition veut i ≥ 0).
    Modification du compteur dans le corps for (int i = 0; i < 10; i++) { i = 15; } Sortie immédiate mais souvent involontaire. Règle : ne jamais modifier i dans le corps.
    ; en trop for (int i = 0; i < 10; i++); { ... } Le ; termine la boucle : le bloc s’exécute une seule fois.

    🔹 3. La boucle while

    3.1 Syntaxe

    while (condition) {
    // Corps : répété tant que la condition est vraie
}
    - La condition est évaluée avant chaque itération. - Si elle est fausse dès le départ → le corps n’est jamais exécuté.

    3.2 Exemple : lire jusqu’à une saisie particulière

    Console.WriteLine("Saisissez un mot ('stop' pour terminer) :");
string saisie = Console.ReadLine();

while (saisie != "stop") {
    Console.WriteLine($"Vous avez saisi : {saisie}");
    saisie = Console.ReadLine(); // ⚠️ INDISPENSABLE pour faire évoluer la condition !
}

Console.WriteLine("Programme terminé.");

    Règle d’or du while :

    "Dans le corps d’un while, il doit toujours y avoir quelque chose qui peut faire devenir la condition fausse. Sinon : boucle infinie."

    3.3 Schéma de boucle "à compteur" équivalent au for

    int i = 1;              // initialisation
while (i <= 5) {         // condition
    Console.WriteLine($"Itération n°{i}");
    i++;                 // incrémentation
}
// Équivalent exact à : for (int i = 1; i <= 5; i++) { ... }
    → Tout for peut s’écrire en while ; on utilise for par convention quand le nombre d’itérations est connu (code plus compact et lisible).

    3.4 Piège classique : boucle infinie

    int n = 0;
while (n < 3) {
    Console.WriteLine(n); // ❌ n ne change jamais → boucle infinie
}
    Conséquence pratique : sous VS Code, arrêter avec Ctrl + C dans le terminal. Faire la démonstration en classe — les étudiants la rencontreront forcément !

    🔹 4. La boucle do-while

    4.1 Syntaxe

    do {
    // Corps : exécuté AU MOINS UNE FOIS
} while (condition);   // ⚠️ ne pas oublier le ; final
    - La condition est évaluée après chaque itération. - Différence fondamentale avec while : le corps est toujours exécuté au moins une fois.

    4.2 Exemple : forcer une saisie valide

    int nombre;
do {
    Console.WriteLine("Saisissez un nombre entre 1 et 10 :");
    nombre = int.Parse(Console.ReadLine());
} while (nombre < 1 || nombre > 10);

Console.WriteLine($"Nombre valide : {nombre}");
    → C’est le cas d’usage idéal du do-while : il faut interroger l’utilisateur au moins une fois avant de pouvoir tester la condition.

    4.3 Comparaison while vs do-while

    // while : 0 itération possible
bool condition = false;
while (condition) {
    Console.WriteLine("Jamais affiché");
}

// do-while : au moins 1 itération
do {
    Console.WriteLine("Affiché une fois");
} while (condition);

    🔹 5. La boucle foreach

    5.1 Syntaxe

    foreach (type element in collection) {
    // Corps : exécuté pour CHAQUE élément de la collection
}

    5.2 Exemples

    // Parcourir un tableau
int[] nombres = { 5, 10, 15, 20 };
foreach (int n in nombres) {
    Console.WriteLine(n);
}

// Parcourir une liste
List<string> prenoms = new List<string> { "Alice", "Bob", "Chloé" };
foreach (string prenom in prenoms) {
    Console.WriteLine($"Bonjour {prenom} !");
}

// Parcourir une chaîne caractère par caractère
string mot = "BTS";
foreach (char c in mot) {
    Console.WriteLine(c);
}

    5.3 foreach vs for sur une collection

    Critère for foreach
    Accès à l’index ✅ Oui (i) ❌ Non (pas de compteur)
    Modification des éléments ✅ Oui (tab[i] = ...) ❌ Interdit
    Simplicité Verbeux Recommandé pour un simple parcours

    Piège : la variable de boucle est en lecture seule : 

    foreach (int n in nombres) {
    n = n * 2; // ❌ Erreur de compilation
}

    🔹 6. break et continue

    6.1 break : sortir immédiatement de la boucle

    for (int i = 1; i <= 100; i++) {
    if (i * i > 50) {
        Console.WriteLine($"Premier carré supérieur à 50 : {i * i}");
        break; // Sort de la boucle dès qu'on a trouvé
    }
}
    → Cas d’usage typique : recherche — on s’arrête dès qu’on a trouvé.

    6.2 continue : passer directement à l’itération suivante

    for (int i = 1; i <= 10; i++) {
    if (i % 2 == 0) {
        continue; // Saute les nombres pairs
    }
    Console.WriteLine(i); // Affiche 1, 3, 5, 7, 9
}

    6.3 Remarques

    • break et continue fonctionnent avec toutes les boucles (for, while, do-while, foreach).
    • Dans des boucles imbriquées, break ne sort que de la boucle la plus interne.
    • Bonne pratique : ne pas en abuser. Un break caché au milieu d’une longue boucle complique la lecture ; parfois, une condition de boucle mieux écrite suffit.

    🔹 7. Tableau récapitulatif et arbres de décision

    Boucle Condition évaluée Itérations minimales Usage principal
    for Avant chaque itération 0 Nombre de répétitions connu
    while Avant chaque itération 0 Répétition conditionnée, éventuellement zéro
    do-while Après chaque itération 1 Action à faire au moins une fois (ex : saisie)
    foreach — (parcours) 0 si collection vide Parcourir une collection

    Questions de vérification rapide (à l’oral) : 1. "Je veux afficher "Bonjour" 10 fois : quelle boucle ?" → for 2. "Je veux lire des mots jusqu’à ce que l’utilisateur tape "stop" : quelle boucle ?" → while 3. "Je veux forcer l’utilisateur à saisir un nombre entre 1 et 10 : quelle boucle ?" → do-while 4. "Je veux afficher tous les éléments d’une liste : quelle boucle ?" → foreach

    💻 Partie TP

    📌 TP 1 : Tables de multiplication (Niveau : Débutant)

    Compétences visées : - Écrire une boucle for simple avec un compteur. - Combiner boucle et opérateur modulo.

    🔹 Énoncé

    Écrire un programme qui : 1. Demande à l’utilisateur un nombre entier. 2. Affiche sa table de multiplication de 1 à 10 (format : 7 x 3 = 21). 3. En bonus de l’énoncé : affiche ensuite tous les nombres pairs de 1 à 100.

    Exemple d’exécution : 

    Saisissez un nombre : 7
7 x 1 = 7
7 x 2 = 14
...
7 x 10 = 70

    🔹 Extensions pour les rapides

    1. Version do-while : répéter le programme tant que l’utilisateur répond o à "Voulez-vous afficher une autre table ?".
    2. Tables complètes : afficher les tables de 1 à 10 sous forme de grille (boucles imbriquées) : 
      1 x 1 = 1   2 x 1 = 2   3 x 1 = 3 ...
1 x 2 = 2   2 x 2 = 4   ...
    3. Saisie robuste : utiliser int.TryParse dans un do-while pour forcer une saisie valide.

    📌 TP 2 : Saisie contrôlée et accumulation (Niveau : Intermédiaire)

    Compétences visées : - Utiliser un do-while pour valider une saisie. - Accumuler un résultat dans une boucle (somme, compteur). - Utiliser while avec une condition de fin saisie par l’utilisateur.

    🔹 Énoncé

    Écrire un programme qui : 1. Demande à l’utilisateur de saisir une note entre 0 et 20 (redemander tant que la saisie est invalide, avec TryParse). 2. Demande ensuite des notes une par une ; l’utilisateur tape fin pour terminer. 3. À la fin, affiche : - Le nombre de notes saisies. - La moyenne (2 décimales). - La meilleure et la moins bonne note.

    Exemple d’exécution : 

    Saisissez une note (0-20) : 25
Note invalide, recommencez.
Saisissez une note (0-20) : 14
Note enregistrée. Tapez 'fin' pour terminer ou saisissez une autre note : 16
Note enregistrée. Tapez 'fin' pour terminer ou saisissez une autre note : 11
Note enregistrée. Tapez 'fin' pour terminer ou saisissez une autre note : fin

Nombre de notes : 3
Moyenne : 13.67
Meilleure note : 16
Moins bonne note : 11

    🔹 Indications méthodologiques (à donner aux étudiants)

    • Pour la première note : do-while (au moins une saisie obligatoire).
    • Pour les suivantes : while (peut ne jamais s’exécuter si l’utilisateur tape fin immédiatement… réfléchir à ce cas !).
    • Penser aux accumulateurs : somme, compteur, initialisés avant la boucle.

    🔹 Extensions pour les rapides

    1. Mention : afficher la mention associée à la moyenne (rappel de la Séance 3).
    2. Valeur sentinelle spéciale : accepter -1 comme code de fin au lieu de fin et discuter la différence.
    3. Rejet des doublons : refuser une note déjà saisie (nécessite une List<double> — anticipation de la Séance 5).

    📌 TP 3 : Jeu "Devine le nombre" complet (Niveau : Avancé — synthèse)

    Compétences visées : - Synthétiser boucles, conditions, Random, TryParse (Séances 2, 3 et 4). - Gérer un compteur d’essais et une condition de sortie complexe (trouvé ou essais épuisés). - Éventuellement imbriquer des boucles (partie + rejouer).

    🔹 Énoncé

    Finaliser le jeu commencé en Séance 2 : 1. Le programme génère un nombre secret entre 1 et 100. 2. L’utilisateur a au maximum 7 essais pour le trouver. 3. À chaque essai : afficher "Trop grand !" ou "Trop petit !", ou "Gagné !" avec le nombre d’essais utilisés. 4. Si les 7 essais sont épuisés : afficher "Perdu ! Le nombre était X". 5. La saisie invalide ne consomme pas d’essai. 6. À la fin, proposer de rejouer (o/n).

    Exemple d’exécution : 

    === Devine le nombre (1-100), 7 essais max ===
Essai 1/7 : 50
Trop grand !
Essai 2/7 : 25
Trop petit !
Essai 3/7 : 37
Gagné ! Trouvé en 3 essais(s).
Voulez-vous rejouer ? (o/n) : n
Au revoir !

    🔹 Indications méthodologiques

    • Deux choix de structure possibles — faire choisir les étudiants et discuter :
      • Un for (int essai = 1; essai <= 7; essai++) avec un break quand c’est gagné ;
      • Un while (!gagne && essais < 7) avec compteur manuel.
    • Penser à une variable booléenne gagne pour sortir de la boucle.

    🔹 Extensions pour les rapides

    1. Mode 2 joueurs : le joueur 1 saisit le nombre secret (avec effacement de la console via Console.Clear() si l’environnement le permet, sinon prévoir un écran d’attente).
    2. Niveaux de difficulté : menu en début de partie (Facile : 1-50, 10 essais / Normal : 1-100, 7 essais / Difficile : 1-1000, 10 essais) — réutiliser le switch de la Séance 3.
    3. Affichage de l’intervalle restant : afficher "Il reste entre 25 et 50" après chaque essai (réduire min/max à chaque itération).
    4. Statistiques de session : compter le nombre de parties jouées et le taux de victoires, affichés à la sortie.

    🔹 Erreurs courantes et remédiation

    Erreur Symptôme Remédiation
    Boucle infinie Programme "figé" Vérifier les 3 zones du for ; vérifier qu’une instruction fait évoluer la condition du while.
    Compteur i utilisé après la boucle Erreur de compilation ("i n’existe pas") i déclaré dans le for est local à la boucle → déclarer la variable avant si besoin.
    ; après le for Corps exécuté une seule fois Montrer l’exemple au vidéoprojecteur.
    Boucle décalée de 1 (10 au lieu de 9 itérations) Résultats faux Toujours tester les bornes avec des petits exemples.

    🎯 Objectifs d’apprentissage validés

    À la fin de cette séance, vous devez être capables de : 1. Choisir la boucle adaptée à une situation (connu / inconnu / au moins une fois / collection). 2. Écrire un for correct (init, condition, incrémentation) et prédire son nombre d’itérations. 3. Écrire un while dont la condition évolue forcément (éviter la boucle infinie). 4. Écrire un do-while de validation de saisie. 5. Utiliser break et continue à bon escient. 6. Accumuler des résultats (somme, compteur, min/max) dans une boucle.
