    B1 1A CSharp Mini projet

    💻 Mini-projet guidé (2h) : « VéloSolidaire »

    Gestion des ateliers de réparation de l’association

    📖 Le besoin fonctionnel

    L’association VéloSolidaire organise des ateliers de réparation gratuits. Des bénévoles y récupèrent des vélos donnés, les réparent et les revendent à prix solidaire. L’association te demande une petite application console pour gérer le stock de vélos en atelier.

    Chaque vélo en stock est décrit par : - une marque (texte) ; - une taille de roue en pouces (nombre) ; - un état : À réparer, Réparé, Vendu.

    Fonctionnalités attendues : 1. Ajouter un vélo reçu (marque, taille, état initial toujours À réparer). 2. Afficher tout le stock (numéroté, avec état). 3. Marquer un vélo comme réparé (par son numéro dans la liste). 4. Marquer un vélo comme vendu (par son numéro) — il sort alors du stock. 5. Statistiques : nombre de vélos au total, à réparer, réparés, et taille de roue la plus fréquente… (voir barème : la stat "taille fréquente" est en extension) 6. Quitter avec un récapitulatif.

    Contraintes techniques : - Un vélo = un string au format "marque|taille|état" → interdit pour l’instant d’utiliser des classes ; on exploite les tableaux et listes du cours. En Séance 7 (POO), on transformera ce projet avec de vraies classes Velo. - Le stock est une List<string>. - Toutes les saisies sont validées (pas de plantage possible).

    🧭 Déroulé guidé — étapes par étapes

    Le projet est découpé en 7 étapes. Le squelette de départ est fourni en Étape 0. À chaque étape : objectif, indications, code attendu. Compilez et testez après chaque étape !

    Étape 0 — Mise en place (5 min)

    dotnet new console -n VeloSolidaire
cd VeloSolidaire
code .

    Remplacer le contenu de Program.cs par ce squelette :

    using System;
using System.Collections.Generic;

class Program {
    static void Main() {
        List<string> stock = new List<string>();
        bool continuer = true;

        while (continuer) {
            Console.WriteLine("\n===== VéloSolidaire — Stock de l'atelier =====");
            Console.WriteLine("1. Ajouter un vélo reçu");
            Console.WriteLine("2. Afficher le stock");
            Console.WriteLine("3. Marquer un vélo comme réparé");
            Console.WriteLine("4. Vendre un vélo (sortie du stock)");
            Console.WriteLine("5. Statistiques");
            Console.WriteLine("6. Quitter");
            Console.Write("Choix : ");

            // À COMPLÉTER aux étapes suivantes
        }
    }
}

    Rappel utile : les actions du menu seront toutes construites sur le même modèle — switch (Séance 3) + List<string> (Séance 5) + TryParse (Séance 2).

    Étape 1 — Lire le choix et gérer les options invalides (10 min)

    Objectif : la saisie du menu ne doit jamais faire planter le programme.

    Indications : - Lire la saisie et la convertir avec int.TryParse. - Si la conversion échoue, afficher un message et revenir au menu (sans compter comme un choix).

    Résultat attendu : 

    if (!int.TryParse(Console.ReadLine(), out int choix)) {
    Console.WriteLine("Saisie invalide, recommencez.");
    continue;
}
switch (choix) {
    case 1: /* étape suivante */ break;
    case 2: /* ... */ break;
    case 3: /* ... */ break;
    case 4: /* ... */ break;
    case 5: /* ... */ break;
    case 6: continuer = false; break;
    default: Console.WriteLine("Option inconnue."); break;
}
    Test : saisir abc, puis 9, puis 6 → aucun plantage, messages corrects.

    Étape 2 — Ajouter un vélo (option 1) (20 min)

    Objectif : saisir marque, taille, état ; construire la chaîne "marque|taille|état" ; l’ajouter au stock.

    Indications : - La marque : texte non vide (!string.IsNullOrEmpty(marque)). - La taille : nombre entier entre 10 et 29 (pouces), validé dans un do-while avec TryParse. - L’état : toujours "À réparer" à la réception (inutile de le demander). - Format de stockage : marque + "|" + taille + "|" + "À réparer", ou avec l’interpolation : $"{marque}|{taille}|À réparer". - Confirmer l’ajout à l’utilisateur.

    Exemple attendu : 

    Marque du vélo : Peugeot
Taille (pouces, 10-29) : 45
Taille (pouces, 10-29) : 26
Vélo ajouté : Peugeot | 26" | À réparer

    Questions à se poser pendant le test : - Que se passe-t-il si la marque est vide ? (le programme doit la refuser) - Deux vélos identiques peuvent-ils exister ? (oui, c’est normal en stock)

    Étape 3 — Afficher le stock (option 2) (15 min)

    Objectif : afficher la liste numérotée, ou un message si le stock est vide.

    Indications : - Si stock.Count == 0 → afficher "Le stock est vide." et arrêter là. - Sinon, parcours avec for (l’index sert pour la numérotation). - Pour un affichage propre, remplacer les | par des espaces… ou plus simple : afficher la chaîne telle quelle, ou la découper avec Split('|') (rappel : string.Split découpe une chaîne en string[] — lien direct avec le cours sur les chaînes).

    Exemple attendu : 

    --- Stock (3 vélo(s)) ---
1. Peugeot  26"  À réparer
2. Gitane   28"  Réparé
3. Btwin    20"  À réparer

    Variante guidée avec Split : 

    string[] parties = stock[i].Split('|');
// parties[0] = marque, parties[1] = taille, parties[2] = état
Console.WriteLine($"{i + 1}. {parties[0]}  {parties[1]}\"  {parties[2]}");

    Test : afficher avec stock vide, puis après 1, 2, 3 ajouts.

    Étape 4 — Marquer un vélo comme réparé (option 3) (20 min)

    Objectif : changer l’état À réparer → Réparé pour un numéro de vélo saisi.

    Indications méthodologiques (dans l’ordre) : 1. Vérifier que le stock n’est pas vide (sinon message et arrêt de l’option). 2. Afficher le stock (réutiliser l’affichage de l’Étape 3 — copier/coller pour l’instant ; la Séance 6 sur les méthodes réglera ce problème !). 3. Demander un numéro (attention : l’utilisateur saisit un numéro 1..N, l’index dans la liste est 0..N-1 → décalage !). 4. Valider : entier entre 1 et stock.Count. 5. Reconstruire la chaîne : découper avec Split('|'), remplacer l’état, reconstituer : 

    string[] parties = stock[index].Split('|');
// Seulement si le vélo n'est pas déjà réparé ou vendu :
stock[index] = $"{parties[0]}|{parties[1]}|Réparé";
    6. Cas particuliers à gérer : vélo déjà réparé → message d’avertissement ; vélo vendu → il n’est plus au stock, ce cas ne devrait jamais apparaître (pourquoi ? à faire justifier).

    Exemple attendu : 

    --- Stock (3 vélo(s)) ---
1. Peugeot  26"  À réparer
2. Gitane   28"  Réparé
3. Btwin    20"  À réparer

Numéro du vélo réparé : 3
Le vélo Btwin est maintenant marqué comme réparé.

    Test : numéro invalide (0, 99, abc), numéro valide, déjà réparé.

    Étape 5 — Vendre un vélo (option 4) (15 min)

    Objectif : un vélo réparé peut être vendu et sort du stock.

    Indications : 1. Stock vide → message. 2. Afficher le stock. 3. Demander le numéro (validation comme à l’Étape 4). 4. Règle de gestion : seuls les vélos à l’état Réparé peuvent être vendus. Sinon → message : "Ce vélo n'est pas encore réparé, il ne peut pas être vendu." 5. Si tout est bon : stock.RemoveAt(index) + message de confirmation avec la marque du vélo vendu.

    Exemple attendu : 

    Numéro du vélo vendu : 3
Vendu ! Le vélo Btwin quitte le stock.

    Question de conception à faire débattre (2 min en binôme) : pourquoi RemoveAt et pas Remove ? (réponse : Remove cherche une valeur ; ici on connaît la position, et deux vélos pourraient avoir la même chaîne).

    Étape 6 — Statistiques (option 5) (15 min)

    Objectif : afficher le tableau de bord de l’atelier.

    Résultat attendu : 

    --- Statistiques ---
Vélos au total   : 5
À réparer        : 2
Réparés          : 3

    Indications : - Parcourir le stock avec foreach, découper chaque chaîne avec Split('|'), comparer parties[2] à "À réparer" / "Réparé", incrémenter des compteurs. - Vérifier que total = aReparer + repares à chaque exécution — c’est un test automatique simple de la cohérence du programme.

    Étape 7 — Quitter (option 6) + finitions (10 min)

    Objectif : récapitulatif de sortie et relecture générale du code.

    Indications : - À la sortie, afficher : "L'atelier contient X vélo(s) dont Y à réparer. Au revoir !" (reprendre les compteurs de l’Étape 6). - Relecture : noms de variables explicites ? Aucun stock[x] sans vérification des bornes ? Toutes les saisies passées par TryParse ?

    🚀 Extensions (pour les plus rapides)

    1. Taille de roue la plus fréquente : compter les occurrences de chaque taille (astuce : un tableau de compteurs indexé par la taille, compteurs[taille]++, puis recherche du max dans ce tableau).
    2. Recherche par marque : option 7 — demander une marque, afficher tous les vélos correspondants (numérotés).
    3. Trier le stock : afficher le stock trié par taille de roue croissante (réfléchir : trier la liste elle-même détruit l’ordre d’arrivée — vaut-il mieux trier une copie ? pourquoi ?).
    4. Historique des ventes : une seconde liste ventes qui enregistre les vélos vendus, et une option pour l’afficher.
    5. Persistance : sauvegarder le stock dans stock.txt à la fermeture, recharger à l’ouverture (File.WriteAllLines / File.ReadAllLines).
