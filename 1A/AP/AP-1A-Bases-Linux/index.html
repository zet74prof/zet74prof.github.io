    AP 1A Bases Linux

    🐧 Bases Linux sous Debian (SISR 1ère Année)

    1. Navigation et Manipulation de Fichiers (Les Fondamentaux)

    Ces commandes sont la base de l'interaction avec le système de fichiers.

    Commande Rôle Exemple Explication
    pwd Print Working Directory. Affiche le chemin absolu du répertoire courant. pwd Savoir où l'on est dans l'arborescence.
    ls List. Affiche le contenu d'un répertoire. ls -lha -l (format long), -h (taille lisible), -a (tous les fichiers, y compris les cachés).
    cd Change Directory. Permet de changer de répertoire. cd /etc/apache2/ Aller au répertoire de configuration d'Apache.
    mkdir Make Directory. Créer un nouveau répertoire. mkdir -p /var/www/test -p permet de créer les répertoires parents s'ils n'existent pas.
    touch Crée un fichier vide ou met à jour la date d'accès/modification d'un fichier existant. touch mon_script.sh Créer un nouveau script.
    cp Copy. Copier des fichiers ou des répertoires. cp fichier.txt /tmp/ Copier fichier.txt dans le répertoire /tmp.
    mv Move. Déplacer ou renommer des fichiers/répertoires. mv old_name.txt new_name.txt Renommer le fichier.
    rm Remove. Supprimer des fichiers. rm -rf dossier -r (récursif, pour les dossiers), -f (force la suppression). ATTENTION DANGER !

    2. Gestion des Droits d'Accès (Chmod & Chown)

    La sécurité Linux repose fondamentalement sur la gestion des droits d'accès. Chaque fichier et répertoire est associé à un propriétaire et à un groupe, et des permissions sont définies pour trois types d'utilisateurs :

    1. user (Propriétaire du fichier)
    2. group (Groupe du fichier)
    3. others (Tous les autres utilisateurs)

    2.1. Les Permissions

    Il existe trois types de permissions, visualisées dans le format long de ls -l (ex: -rwxr-xr--):

    Lettre Numérique (Octal) Rôle (Fichier) Rôle (Répertoire)
    r 4 Read : Lire le contenu du fichier. Lister le contenu du répertoire.
    w 2 Write : Modifier ou supprimer le fichier. Créer, renommer ou supprimer des fichiers/répertoires dans ce répertoire.
    x 1 Execute : Exécuter le fichier (si c'est un programme ou un script). Y accéder (s'y déplacer avec cd).

    2.2. Commande chmod (CHange MODe)

    Elle modifie les permissions d'un fichier ou d'un répertoire.

    • Mode symbolique (Utilisation de u, g, o, a pour all) :

      • chmod u+x mon_script.sh : Ajoute le droit d'exécution au propriétaire.
      • chmod go-w fichier.txt : Retire le droit d'écriture au groupe et aux autres.

    • Mode octal (Le plus précis pour le SISR) : On additionne les valeurs numériques ($4+2+1=7$) pour chaque catégorie.

      • $750$ signifie :
        • Propriétaire : $7$ (rwx)
        • Groupe : $5$ (r-x : lecture et exécution)
        • Autres : $0$ (--- : aucun droit)
      • Exemple : chmod 750 mon_dossier

    2.3. Commande chown (CHange OWNer)

    Elle modifie le propriétaire et/ou le groupe d'un fichier/répertoire.

    • sudo chown user:group fichier
      • sudo chown prof_sio:adm_web /var/www/site : Définit prof_sio comme propriétaire et adm_web comme groupe du répertoire.
      • sudo chown -R www-data:www-data /var/www/html : Change récursivement (-R) le propriétaire et le groupe de tous les fichiers d'un site à l'utilisateur et groupe d'Apache.

    3. Gestion des Privilèges et des Services

    3.1. Commande sudo (SuperUser DO)

    sudo permet à un utilisateur autorisé d'exécuter une commande avec les privilèges d'un autre utilisateur, généralement l'utilisateur root (administrateur).

    • Rôle : Exécuter une commande critique (installation, redémarrage de service, modification de fichiers système) sans se connecter directement en root.
    • Exemple : sudo systemctl restart apache2

    3.2. Gestion des Services avec systemctl

    systemctl est l'outil standard (Systemd) pour gérer les services (ou démons) sur Debian 13 (Apache, SSH, MariaDB, etc.).

    Commande Rôle Exemple
    start Démarre un service. sudo systemctl start apache2
    stop Arrête un service. sudo systemctl stop apache2
    restart Arrête puis redémarre un service (nécessaire après modification d'une configuration majeure). sudo systemctl restart apache2
    reload Recharge la configuration sans interrompre les connexions existantes (si le service le supporte). sudo systemctl reload apache2
    status Affiche l'état du service (actif, inactif, en échec) et les dernières lignes de log. Indispensable pour le diagnostic ! systemctl status apache2
    enable Active le démarrage automatique du service au boot du système. sudo systemctl enable apache2
    disable Désactive le démarrage automatique du service au boot. sudo systemctl disable apache2

    4. Gestion des Paquets avec apt

    Le système de gestion de paquets APT (Advanced Package Tool) est la méthode standard pour installer, mettre à jour et supprimer des logiciels sur Debian.

    Commande Rôle Exemple
    update Met à jour la liste des paquets disponibles (l'index des dépôts). Toujours faire ceci en premier ! sudo apt update
    upgrade Installe les versions plus récentes des paquets déjà installés. sudo apt upgrade
    install Installe de nouveaux paquets. sudo apt install mariadb-server
    remove Supprime un paquet (laisse les fichiers de configuration). sudo apt remove apache2
    purge Supprime un paquet et ses fichiers de configuration. (Plus propre !) sudo apt purge apache2

    5. Automatisation : Scripts Shell et Planification (Cron)

    L'administrateur SISR doit automatiser les tâches répétitives (sauvegardes, mises à jour, nettoyage).

    5.1. Écrire un Script Shell

    Un script shell est un fichier texte contenant une suite de commandes Linux qui seront exécutées séquentiellement.

    1. L'entête : La première ligne doit indiquer au système quel interpréteur utiliser. Pour Bash (le shell par défaut) : #!/bin/bash

    2. Exemple de script simple (sauvegarde.sh) :

      #!/bin/bash

# Définition des variables
JOUR=$(date +%Y-%m-%d)
SOURCE_DIR="/var/www/site"
DEST_DIR="/home/backup/web"

# Affichage d'un message
echo "--- Début de la sauvegarde du $JOUR ---"

# Commande de compression des données
tar -czf "$DEST_DIR/web_backup_$JOUR.tar.gz" "$SOURCE_DIR"

echo "Sauvegarde terminée et stockée dans $DEST_DIR"

    3. Rendre le script exécutable : chmod u+x sauvegarde.sh

    5.2. Planification avec cron

    cron est le service d'ordonnancement de tâches (scheduler) qui permet d'exécuter des commandes ou des scripts à intervalles réguliers (minute, heure, jour, mois...). Les tâches sont définies dans la crontab (cron table).

    • Éditer votre crontab : crontab -e
    • Format d'une ligne crontab : m h dom mon dow commande
    Champ Valeurs Possibles Description
    m $0-59$ Minute
    h $0-23$ Heure
    dom $1-31$ Jour du Mois
    mon $1-12$ Mois
    dow $0-7$ Jour de la Semaine ($0$ ou $7$ = dimanche)

    • Exemple Crontab : Exécuter le script de sauvegarde tous les jours à 2h30 du matin.

      30 2 * * * /chemin/absolu/vers/sauvegarde.sh

      (* signifie "toutes les valeurs possibles").
